# Live Mac checks, October 27, 2026

App: Wisply 1.11.0 (202610221510), signed by TestFlight Beta Distribution,
bundle `fallah.Wisply`, macOS 27.0.1. This is beta-build evidence, not proof
that the required features are available in the public App Store release.

The vendored app commit is `92f8939ed3208a69deaa112aa3aa74a67933d3a4`.
Its `MCPServer.swift` sets `allowLocalEndpointReuse = false` and binds IPv4
loopback. The installed beta's source commit was not embedded in its About
screen; the live result below is separate corroboration.

No token or memo content is included in this report. Search used a synthetic
query. The other read calls exercised existing local data without including
their payloads in the report. The recording test used microphone-only capture
with coaching temporarily off. Its token stayed in process memory and was not
saved over the read-only Keychain item. No cloud-AI request was started by the
test.

The first unauthenticated GET expectation was corrected: authorization runs
before the method check, so GET without a token returns401; GET with the
verified token returns405.

The first recording attempt exceeded the connector request budget while the
app displayed Preparing speech. Cancel did not visibly clear that state, so
both access switches were turned off and the app was quit. A later attempt
passed after reopening. The original timeout remains under investigation;
the successful retry does not establish reliable first-run preparation.

After the successful test, MCP and recording control were returned off, the
original audio-capture and coaching preferences were restored, and the app
was quit. There was no listener on port51771 or running Wisply process.

Full-access token flows, first-run recording preparation and public App Store
version readiness remain unverified. This report does not clear the registry
namespace, npm ownership policy or publication gates.
